### 六个踩坑（详见 docs/doris-deployment-record.md §4）
1. Doris 3.x/4.x FE 读 `JAVA_OPTS_FOR_JDK_17` 而非 `JAVA_OPTS`，默认 Xmx8192m 会在 8G 机器上 OOM。
2. BE 4.x 也需要 JAVA_HOME（JNI 依赖），be.conf 里配。
3. 无 BE 时 `SELECT 1` 都失败（Doris 全部查询走 BE），探活要用 SHOW 命令。
4. 本地脚本超时 SIGTERM 会杀死远端 SSH 会话内的安装 → 长任务必须远端 nohup 分离 + 轮询。
5. 动态分区默认 `history_partition_num=0` 不建历史分区，且动态分区表禁止手工 ADD PARTITION，需先 disable 再补再 enable。
6. 4.0 不支持老语法 `GRANT USAGE_PRIV ON RESOURCE GROUP`。

### 三个脚本坑（写同类脚本必看）
1. **bash `IFS=$'\t' read -a` 会折叠空字段**：SHOW BACKENDS 的 ErrMsg 为空时，其后所有列左移一位，导致 CPU/内存列错位。解析 TSV 一律用 `awk -F'\t'`（保留空字段）或 `cut -f`。
2. `SHOW PROC '/statistic'` 与 tablet_health 的汇总行是 `$1=="Total"`（不是 $2）。
3. `SHOW FRONTENDS` 的 IP 列名是 `Host`；ClusterId 在第 10 列，按表头定位更稳。

### 重要发现：3 个调优参数在 4.0.8 中根本不生效
- `max_query_concurrency`（FE）**已被移除**，4.x 用 `ALTER WORKLOAD GROUP normal PROPERTIES ("max_concurrency"="32")`；实测 normal 组是 2147483647（无限制）。
- `streaming_load_max_mb` **属于 BE 不是 FE**（默认 102400），放进 fe.conf 无效。
- `compaction_max_memory_limit_percent` **不存在**，4.x 用字节值 `compaction_memory_bytes_limit`（默认 1G）。
- **Doris 对未知 conf 键静默忽略**，启动只打 WARN，`ADMIN SHOW CONFIG` 也查不到 → 必须拿运行时值与基线比对才能发现。
