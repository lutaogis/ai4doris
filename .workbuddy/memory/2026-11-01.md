## 关机方案（21:30-21:50）

**交付 `docs/doris-shutdown-guide.md` + `scripts/07-stop-cluster.sh`（停机）+ `scripts/08-start-cluster.sh`（开机），两脚本已在 51 实跑验证。**

### 四个实测硬事实（写方案必须基于这些）
1. **`stop_fe.sh` / `stop_be.sh` 默认 `signum=9`（kill -9）**，只有传 `--grace` 才是 SIGTERM(15)。原 systemd unit 的 `ExecStop` 没带 `--grace` → `systemctl stop` 等于硬杀。**已修 unit**（加 `--grace`/`PIDFile`/`KillSignal=SIGTERM`/`TimeoutStopSec=180`）并同步六台 + daemon-reload + verify 通过。
2. **systemd 是 enabled 但 inactive**（进程是部署时手工 `start_fe.sh --daemon` 起的）→ `systemctl stop` 会「假成功」，什么都不做。判断方法：`systemctl is-active` = inactive 而 `pgrep` 有进程。
3. **FE 至今无 image**：journal 13513 持续增长，`meta/image/` 只有 ROLE/VERSION/DEPLOY_MODE。`ALTER SYSTEM CREATE IMAGE` 在 4.0.8 **语法不存在**（parse error）；置 `force_do_metadata_checkpoint=true` 观察 100s 仍 `last=0 current finalized=0`，image 不生成。→ 关机前**必须冷备 `fe/meta`**（9.1M，tar 秒级）。
4. **pid 文件位置**：FE `/opt/doris/fe/bin/fe.pid`、BE `/opt/doris/be/bin/be.pid`；停止脚本必须以 doris 用户跑（`sudo -u doris`）。sudo 需密码（lumz 在 sudo 组）。

### 顺序与验证
- 关机：BE(54/55/56) → FE Follower(52/53) → FE Master(51)；开机反过来。理由：BE graceful 需 FE 在线接收退出通知。
- **实测 52（FE）**：`stop_fe.sh --grace` 8s 退出 → `systemctl start doris-fe` active(MainPID 43423) → 30s 内重新 Join，FOLLOWER alive。
- **实测 56（BE）**：`stop_be.sh --grace` 5s 退出 → `systemctl start doris-be` active(12853) → 45s 内 tablet 回到 103/103 healthy。
- `07 --dry-run` 通过：FE 3/3、BE 3/3、tablet 103/103、备份落 `/opt/doris/backup/fe-meta-*.tar.gz` + 复制 `/opt/ai4doris/backup/`。

### 脚本踩坑
- **mysql 用 `-N` 无表头**，awk 不能用 `NR>1` 跳首行（会漏一条，导致 FE 显示 2/3、BE 所有行都被当数据仍算对）；列位置：FE Alive=$12/IsMaster=$9/Role=$8，BE Alive=$10。
- `$()` 内嵌 awk 时双引号必须成对，`'...PENDING")"` 这种笔误会让整个脚本 `unexpected EOF`（bash 只报最后一行号，难定位）。
- Windows 本地无 sshpass → 脚本必须在 node-01 执行；上传用 base64 + exec（sftp 子系统在这批机器上返回 ENOENT）；Git Bash 需 `MSYS_NO_PATHCONV=1` 否则 `/home/...` 被改写成本地路径。

## 集群正式停机（21:48-21:55，已下电）

**六台全部断电，`ping` 全不通。备份 `/opt/doris/backup/fe-meta-20261101_214837.tar.gz`（同时复制 `/opt/ai4doris/backup/`）。**

### 执行中暴露的第 7 个坑（最关键）
**用 `stop_fe.sh --grace` / `stop_be.sh --grace` 去停「systemd 托管」的节点，15 秒后会被自动拉起。**
- 现象：21:50:52 停 52 显示已退出，21:51:20 校验时 FE 又活了；56 的 BE 同样复活。
- 根因：52/56 当天被 `systemctl start` 接管，unit 里 `Restart=on-failure`，SIGTERM 退出被判 failure → `RestartSec=15` 重启。
- 修法：脚本新增 `stop_component()`，先 `systemctl is-active`，active 用 `systemctl stop`，否则用 `bin/stop_*.sh --grace`。
- **代价说明**：本次正是阶段 5 残留校验拦住了 poweroff，否则会「进程被重建 → 机器下电强杀」，等于白停。

### 关键结论
- 停 BE 后 `stop_be.sh --grace` 的"已停止（0s）"是因为进程已退出，计时从 0 开始，属正常。
- 只有 52 由 systemd 接管（FE）、56（BE）；51/53 FE、54/55 BE 仍是手工启动 → 停完不复活的差异来源。
- 51 被清后再 `shutdown -h +1`，六台 ping 全不通（Windows 侧验证）。
